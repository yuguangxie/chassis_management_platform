# 桌面端 UI 一致性与显示问题专项审计（2026-07-23）

## 1. 审计结论

当前 11 个业务页面已经具备统一的深蓝工业风框架，但**尚未达到桌面产品视觉收口标准**。本轮在 Mock/127.0.0.1 回环环境中确认了 4 类高优先级问题：交互控件并非真实控件、实时状态在 REST 与 WebSocket 间来回跳变、1366×768 下内容被裁切、图表与筛选控件文字重叠或截断。中文化、按钮体系、1920×1080 空白利用率和灯光状态效果也没有形成全局一致规则。

本次审计结论为：**功能主链可继续 Mock 联调，UI 一致性整改未完成，不建议按当前界面作为产线操作终版验收。**

本轮只新增审计文档与截图证据，没有修改页面实现、CAN 发送策略或后端安全边界。后续实施 Prompt 见 [桌面端 UI 统一优化实施 Prompt](../reference/DESKTOP_UI_OPTIMIZATION_PROMPT_2026-07-23.md)。

## 5. 用户所报问题的根因审计

### 5.1 网络配置开关无法使用

`NetworkConfigPage.vue` 中的 `ToggleVisual` 只渲染 `<span>`，没有 `@click`、`emit`、`role="switch"`、`aria-checked` 或键盘处理。页面虽然显示绿色开关，但用户无法改变草稿值。另有两个语义问题：

1. API 的 `tx_enabled` 当前由后端 `ChannelConfig.enabled` 映射而来，实际更接近“通道启用”，不应未经澄清直接标成“发送允许”。
2. CAN1 当前禁止作为控制通道；后续不能为了让控件“可点”而扩大主动发送能力。CAN1 的主动发送/控制权限应锁定关闭并显示安全原因；CAN2 可在管理员权限和配置应用闭环内做允许范围内的开关。

推荐整改：使用共享、可访问的 `ToggleSwitch`；区分“通道启用”“主动发送权限”“默认控制通道”；默认控制通道使用互斥选择；修改只进入草稿，经过“保存并应用 → 后端校验 → 健康检查 → 失败回滚 → 审计”后生效。

### 5.2 信号仪表盘 `unavailable` 周期跳变

根因已经明确：

- REST `/signals/dashboard` 返回顶层 `quality/mock/updated_at` 元数据。
- WebSocket `signals.dashboard` 直接广播 `SignalStore.dashboard_summary()`，其质量在 `status.quality`，没有同形的顶层 `quality`。
- 前端 WS handler 用整个 payload 覆盖 `dashboard`，随后页面读取 `data.quality`；值变成 `undefined`，最终显示 `unavailable`。
- 每 2500 ms 的 HTTP 轮询又返回顶层 `quality=good`，因此短暂恢复正常；下一次 10 Hz WS 推送再次覆盖。

连续采样显示每约 2.5 秒短暂正常，其余时间 7 个卡片显示 `unavailable`。这不是用户错觉，也不是单纯的信号 freshness 阈值问题。

推荐整改：REST 与 WebSocket 使用同一响应模型；后端推送完整 envelope，前端仍做兼容归一化。不得用顶层缺字段推导不可用，也不得在数据仍可用时反复清空图表。`unavailable/stale/invalid/mock` 必须分别表达。

### 5.3 CAN 监控筛选项显示不全

1366 断点下，过滤栏固定列宽分别只有 148/130/100 px 等，而全局 `.segmented button` 的 `min-width` 为 70 px：

- 通道 3 项至少需要 210 px，当前列只有 148 px；
- 方向 3 项至少需要 210 px，当前列只有 130 px；
- Hex/Dec 2 项至少需要 140 px，当前列只有 100 px。

父容器设置 `overflow:hidden`，因此选项不是换行，而是被直接裁切。应采用按选项数量均分的局部分段组件，在 1366 下把过滤区重排成两行，且用“全部/接收/发送/十六进制/十进制”中文标签。

### 5.4 实时曲线加载不存在的检测会话

页面把 `sessionId` 默认写死为 `EOL-20260401-0001`，并在所有模式的 `onMounted` 中无条件请求 replay 和 fault-events。实时模式没有历史会话也会发起请求，404 被写入共享 `signals.error`，形成“加载失败：检测会话不存在（trace...）”。

推荐整改：

- 实时模式只加载 curve config 和实时 timeseries；
- 只有路由明确为 `mode=history` 且 `session_id` 非空时加载 replay/fault-events；
- 会话必须来自真实历史列表或路由，不得使用硬编码演示 ID；
- 历史会话无效时只在回放区域显示中文错误，不污染实时曲线；
- 将 `trace:` 改为“追踪编号：”。

### 5.5 一键检测和告警诊断按钮闪烁

短时运行采样没有捕获到稳定的 disabled/opacity 转换，因此本项不能写成“本环境完全动态复现”。但代码存在明确触发条件：

- `eol.loadDashboard()`、`alarms.loadDashboard()` 每次后台刷新都设置共享 `loading=true`；
- 操作按钮直接绑定 `:disabled="loading"`；
- 两页每 2.5 秒轮询；告警页还在 WS 告警事件到达后再次 GET，检测运行时 EOL 多个 WS topic 也会触发 GET。

这会让后台刷新改变按钮禁用态，并可能造成闪烁、色彩饱和度变化或交互抢占。应拆分 `initialLoading/refreshing/actionPending`，背景刷新不得禁用按钮；高频 WS 应直接增量更新或节流合并请求。

### 5.6 页面未铺满与 1366 内容裁切

两个问题来自同一类固定行高设计，但方向相反：

- 手动控制固定行高合计小于 1920×1080 可用高度，底部约空 89 px；
- 一键检测固定行高合计小于可用高度，底部约空 79 px；
- 总览和网络配置在 1366×768 下固定行高合计大于可用高度，页面根节点分别超出约 158/160 px；外层 `.content` 禁止滚动，内容不可达。

旧 E2E 只断言 document 没有滚动条，没有断言页面所有一级区块均在内容容器内，因此把“内容被裁切”误判成“无页面级滚动通过”。后续必须同时断言 `pageRect.bottom <= contentRect.bottom`，内部滚动区另行检查。

### 5.7 灯光与制动灯效

当前 `LightItem` 的 `active/danger` 是调用处静态传入：位置灯始终带绿色 active 样式，制动请求即使为 OFF 也始终显示红色图标；左右转灯和近光灯没有按实际状态点亮。

目标状态应为：

| 信号 | 使能颜色 | 关闭/不可用 |
|---|---|---|
| 左转灯、右转灯 | 黄色光效 `#F6C343` | 中性灰，无光晕 |
| 位置灯 | 红色光效 `#EF4444` | 中性灰，无光晕 |
| 近光灯 | 白色光效 `#F8FAFC` | 中性灰，无光晕 |
| 制动请求 | 红色光效 `#EF4444` | 中性灰，无光晕 |

使能必须由真实状态值归一化后决定；stale/invalid/unavailable 必须优先覆盖为中性未知态，不能保留最后一次“点亮”造成误判。

## 7. 全局一致性结论

### 7.1 按钮

告警诊断页的主要操作按钮可作为视觉基线，但不应把所有小型筛选按钮都强制做成 70 px。建议抽取两类共享组件：

- `IndustrialButton`：32/36 px，用于标题栏、筛选、表格和普通操作；
- `IndustrialActionButton`：70 px，用于页面底部主要操作，沿用告警诊断的图标块、渐变、危险色和 hover 高亮。

所有按钮共享 primary/neutral/warning/danger、disabled、loading、focus-visible、hover 规则。hover 应包含亮度、边框和轻微光晕，使用 140～180 ms transition；disabled 不执行 hover。急停、安全停车和删除等危险动作不能因统一样式而弱化。

### 7.2 中文化

用户可见状态必须使用统一字典：

- online/offline → 在线/离线；
- unavailable/stale/invalid → 不可用/数据陈旧/无效；
- Normal/Warning/Fault/Critical → 正常/警告/故障/严重；
- PASS/FAIL/RUNNING/ABORTED/WAIT → 通过/失败/运行中/已中止/等待；
- admin/operator/engineer/viewer → 管理员/操作员/工程师/查看者；
- Manual/Remote/Auto → 手动/远程/自动；
- ON/OFF/RELEASED → 开启/关闭/已释放；
- ALL/RX/TX/Hex/Dec → 全部/接收/发送/十六进制/十进制。

CAN、DBC、BMS、VIN、SOC、PDF、CSV 等标准缩写可以保留，但应采用中文优先写法，例如“车辆识别码（VIN）”“十六进制（Hex）”，不能继续暴露原始英文业务状态。

### 7.3 图表

实时曲线在 1366×768 中把 6 张图压缩进 3 行，图例、多 Y 轴和时间轴没有足够绘图区。后续应按视口切换图表布局，而不是继续缩小字号：1920 使用 2×3；1366 使用分组页签或 2×2 活动图表，并在实时模式收起历史回放区。图例使用滚动/截断、轴标签启用 `hideOverlap`、限制时间刻度数量，完整名称放入 tooltip。

## 8. 验收门槛

后续 UI 优化必须同时满足：

1. 1366×768 与 1920×1080 下 11 页根节点完全位于 `.content` 内；无页面级滚动，内部表格/列表滚动可达。
2. 通道、方向、进制的所有选项完整可见并能通过鼠标和键盘操作。
3. 信号仪表盘连续 60 秒不在正常与 unavailable 间抖动；每种质量状态有确定的中文显示。
4. 实时模式不请求任何历史会话 API；无 session 时不出现 404。
5. 一键检测/告警页背景刷新不改变主要按钮 DOM 节点、禁用态和透明度。
6. 主要操作按钮全部使用共享组件；悬停有高亮，键盘有焦点环，禁用态有原因。
7. 用户可见业务状态没有未批准英文词；技术缩写符合中文优先词典。
8. 灯光使能颜色符合本审计表，stale/invalid 时不保留点亮状态。
9. 图表标题、图例、坐标轴、数据标签不互相覆盖，也不超出卡片。
10. 不改变车辆安全边界：CAN1 不获得主动控制权限，只允许 CAN2 的 0x121，0x123/0x126/NMT 保持禁用。

## 9. 未确认项

- 用户报告的按钮闪烁在本轮短时正常场景中没有稳定捕获，需要在运行中检测会话、告警事件持续推送以及 30～60 分钟联调条件下补充录屏/节点状态证据。
- 当前只验证 100% Windows 缩放的逻辑视口；125%/150% 缩放、触摸屏、字体替换和远程桌面缩放仍需干净 Windows 工控机验证。
- 图表文字重叠的最终可读阈值需要产品确认最小字号、最少绘图区高度和允许同时展示的 series 数量。
