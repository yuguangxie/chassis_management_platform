# 风险与未确认问题（当前实现）

更新日期：2026-07-22。当前身份、路由守卫、全接口鉴权、签名配置生命周期和真实网络诊断已完成 Mock/回环软件收口，但这不构成真实车辆上线批准。

## 已收口的软件问题

- P0-05：移除静态开发身份，加入一次性 bootstrap、本地账户、短 session、锁屏/过期/撤销/失败限制和审计。
- P0-06：production 必须加载本机签名 active package；schema 覆盖网络/CAN/source/车型/DBC/方案/路径/工位/打印机，应用有预检和回滚。
- P1-05：网络诊断来自 OS socket 和运行统计；UDP 不伪造 ping，报告绑定、endpoint、批准来源收帧年龄和 TCP 状态。
- P1-09：桌面端完成 JSON 文件导入、签名/schema 校验、diff/阻断预览、显式 APPLY；仅 admin。
- P1-15/P1-20：OpenAPI 和 150 操作授权矩阵从代码生成；除最小 health 和身份入口外全部敏感 API 需要 session。
- P1-06/P1-07/P1-08：唯一 data_root、正式 v1→v3 migration、online backup/校验恢复、归档保护和可取消 retention 已完成软件收口。
- P1-10/P1-11：数据库/磁盘故障联锁、四格式真实报告、依赖检查、持久化打印状态机和虚拟打印回归已完成软件收口。

## 残余风险

1. 当前本地 HMAC key 的安全性取决于 Windows 服务账户和秘密存储；尚无 TPM/HSM、轮换和双人密钥托管。
2. token 存在 renderer sessionStorage，XSS/renderer compromise 仍可能窃取当前短 session；需 CSP、依赖治理、安装签名和 OS 加固。
3. production 配置只有在真实批准来源持续发帧时才能通过应用后健康检查；当前仅以回环 Mock 验证回滚逻辑，未验证现场网卡/防火墙/USR-CAN115。
4. 本轮只在临时目录注入低空间、权限、锁和损坏故障；真实数据盘 ACL、磁盘配额、杀毒软件锁定、断电恢复和大库耗时仍需干净工控机演练。
5. Windows spooler 实现尚未用获批物理打印机验证。RAW PDF 是否被目标驱动接受、任务移出队列后的完成语义和纸面版式必须现场确认。
6. 当前备份目标仍在同一 data_root；异盘/离线介质复制、加密、RPO/RTO、保留代数和灾备恢复责任人尚需工厂制度确认。
7. Electron Builder/NSIS、离线 Python sidecar、动态回环端口、每次启动凭据、受控日志、有界重启、优雅退出、单实例、SBOM/hash/manifest 和安装态 11 页回环验证已完成。当前实际产物仍是 `unsigned-internal`；独立普通用户干净 VM、企业杀毒/防火墙、批准历史版本升级/回滚 fixture 和正式代码签名证书尚未完成，因此不得标记正式生产发行。
8. 物理急停、安全 PLC/继电器、底盘看门狗和 safe-stop 硬件行为仍未确认。只能 Mock/127.0.0.1，禁止据此连接可运动执行器。
9. 当前安装器使用仓库内“内部评估许可声明”和 Electron 默认图标。正式 publisher 法定名称、最终许可文本、商标/产品图标和证书主体需由项目所有者、法务与 IT 发布方批准后替换；这不影响回环内测，但阻断正式品牌发行。
10. 11 个桌面页面的主要读写链路、统一状态和安全交互 E2E 已收口；仍禁用的布局编辑器、CAN 详情子页签、告警分页、报告关联数据分标签和直接 DBC 文件选择没有后端契约，禁止仅用 Toast 或静态数组恢复为“可用”。
11. 页面测试中的打印使用虚拟后端，配置导入使用运行时随机签名包，车辆数据使用 Mock/回环。真实显示器缩放、触屏、物理打印机、长时间高帧率渲染和现场操作节拍仍需干净 Windows 工控机验证。
