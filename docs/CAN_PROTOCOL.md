# USR-CAN115 与 UDP 来源安全

更新日期：2026-07-21。验证边界仅为 Mock 与 `127.0.0.1`。

## 13 字节标准转换帧

- Byte0：Bit7 FF、Bit6 RTR、Bit5..4 保留位必须为 0、Bit3..0 DLC 0..8。
- Byte1..4：CAN ID，大端。
- Byte5..12：固定 8 字节数据区；发送数据不足补 0，UI 有效数据按 DLC 截取。
- 编码拒绝 DLC 越界、数据区超过 8 字节和不在 0..255 的字节。
- 标准帧 CAN ID 只能为 `0..0x7FF`；扩展帧只能为 `0..0x1FFFFFFF`。
- 解码发现非法保留位、DLC 或 CAN ID 时标记协议错误；网关不更新在线状态、不入处理队列、不更新信号缓存。

RTR 位保留并可往返解析；固定 8 字节适配器数据区仍按 DLC 表达请求长度。实际设备对 RTR 填充区的行为仍需只监听台架确认。

## UDP 授权来源

每个通道默认 `validate_source_endpoint=true`，接收数据报必须同时匹配该通道配置的 `device_ip` 与 `simulated_device_port`（存在时）或 `device_port`。

非授权来源的处理顺序是：先计入 `unauthorized_datagrams` 和最近来源，再按 5 秒节流记录安全日志/严重告警，随后丢弃。该数据报不会进入 codec/接收队列，不会增加 `rx_count`，不会更新 `last_frame`、`last_receive`、`online` 或任何解码信号。

本限制是精确 endpoint 过滤，不是主机防火墙替代品。production 仍需要隔离网络、交换机/防火墙白名单、设备固定地址和现场抓包确认。

## 发送边界

运行时 allowlist 保持 `{0x121}`，且唯一控制通道为 CAN2。`0x123`、`0x126`、`0x710`、`0x715` 和 CANopen NMT 仍默认禁用。本工作包没有扩大主动发送范围。
